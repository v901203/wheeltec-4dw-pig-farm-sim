# 幾何診斷、假路口修正與 BC → PPO

只在隔離 Gazebo 訓練環境使用學習策略。正式實車巡邏入口仍為傳統控制器；
本次不會自動部署模型或啟動 UART。

## 先記錄，再修正

Gazebo 評估加上 `--geometry-diagnostics`，會在該次日誌的 `geometry/` 保存：

- `decisions.jsonl.gz`：掃描時間、階段、候選中心／路寬、牆線配對、
  開口兩側與內部點數、信心度、拒絕原因，以及最近的牆面追蹤配對。
- `scans_*.npz`：完整原始雷達，每塊最多 64 幀；JSON 的 `raw_chunk`、`raw_index` 對應原始掃描。
- 模擬真實位姿僅供離線稽核，沒有輸入定位器、BC 或 PPO。

幾何取得前原本以整面牆的點數當分母，遠方大量點數會稀釋開口內殘留牆點。
現在以開口較弱一側的支撐量限制內部點數，避免「內部仍有牆」被誤判為通路。
連續相容的新中心若與舊追蹤矛盾達確認幀數，先停車，再獨立取得新中心；
保留原路線狀態、路口／端點計數與朝向身份。
沒有放寬 0.25 m 跳動門檻、5 cm 置中門檻或障礙淨空。

學習環境不再把第一次重新定位立即視為回合失敗：等待期間輸出零速度，
取得連續有效幾何後恢復同一階段。每次等待最多 50 步（10 模擬秒），
每回合最多 3 次，超限則結束回合；這些上限不作移動距離或動作完成依據。
無效幾何期間的教師標籤仍排除，不能當成「應該永遠停車」的 BC 示範。

## 在正式巡邏保存診斷（可選）

預設不寫逐幀幾何檔。需要時，在已載入 ROS 的環境設定：

```bash
PIG_PEN_GEOMETRY_LOG_DIR=logs/geometry /usr/bin/python3 rl_pig_pen/fsm_lidar_patrol.py
```

每次建立獨立目錄，原始資料分塊壓縮，第一次故障／重新定位會提早寫出目前區塊，
正常結束寫完最後未滿區塊。紀錄不參與控制；串口與速度介面不變。
`control_modes.py` 的 PATROL 路徑同樣使用這個選項。

## 舊模型與資料

輸入仍為 161×4=644 維，但幾何演算法與恢復流程改變，原環境雜湊不再相同。
`transfer_checkpoint.py` 只允許 FSM／定位／混合環境程式差異，
複製原權重至新目錄並記錄差異，標記必須重新評估；不覆蓋舊模型，也不宣稱舊結果仍有效。
地圖、機器人、配置、感測／動作編碼變動仍會拒絕轉移。

舊 v5 雷達示範可用 `upgrade_demos.py --allow-teacher-replay --skip-incompatible`
逐幀重播；只有狀態與教師指令完全重現的整回合才能保留。
本輪 90 回合中保留 34、排除 56，左轉需重新收集；不放寬比對誤差以強行沿用。
重新收集的正常資料另作完整回合分割，舊正常資料沿用原 train／validation／test 身份。
DAgger 永遠只進 train。

`train_bc.py --init-model '<相容BC.zip>'` 以原權重微調，
若 validation 沒改善就保留初始模型；不是重新隨機初始化。

## PPO 啟動門檻與初始微調

先以固定 BC 模型測試並存幾何紀錄，再執行：

```bash
/usr/bin/python3 rl_junction/assess_geometry.py --evaluation '<完整評估目錄>'
```

門檻至少每項 2 回合、每項有有效幾何，已取得路口時中心誤差不得超過 10 cm，
不得留下未恢復的幾何錯誤，且環境須與目前相同。
這是有限回歸檢查，不是實車安全證明；成功率與停滯另外統計，不能混為定位能力。

通過後才可啟動，例如：

```bash
/usr/bin/python3 rl_junction/train.py --init-model '<微調BC.zip>' \
  --geometry-gate '<該模型的評估目錄>/geometry_gate.json' \
  --timesteps 1024 --n-steps 256 --batch-size 64 --n-epochs 4 \
  --learning-rate 0.00001 --critic-warmup-rollouts 1 \
  --max-steps 300 --task-sampling round-robin --torch-threads 1 --seed 70000
```

會核對門檻內的環境及模型 SHA256。第一個 rollout 只更新價值網路，
避免 BC 未訓練的 critic 立即帶偏 actor；之後才允許小幅 PPO 更新，
clip_range=0.1、target_kl=0.01。僅學習路口區間，FSM 仍負責直線巡邏與安全保護。
短版預設三項任務依序輪替，每回合上限 60 模擬秒，避免單一停滯回合佔滿 rollout。
`--task-sampling random` 可改為隨機任務；小步數隨機抽樣不保證涵蓋全部技能。
每個已完成 rollout 保存 `latest.zip` 與 `progress.json`；正式完成才寫 `model.zip` 與 `completion.json`。
1024 步是初始微調，不代表收斂或優於 BC；完成後需用獨立種子與 BC 比較。

若幾何門檻未通過，或重新收集資料不完整，流程應停下排查，不能跳到 PPO。
